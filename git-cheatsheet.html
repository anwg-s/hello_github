这张卡片把概念、图形界面、命令行三部分压在一张纸上。忘了就翻，不用重学。

一、先分清两个东西

Git
装在你电脑上的版本记录工具。像游戏存档，每次改动存一份，随时能回到上一版。
GitHub
云端网站，用来存放 Git 仓库。像网盘 + 协作平台 + 作品展示页。

二、五个核心词

仓库 Repository
一个被 Git 管理的项目文件夹。仓库就是普通文件夹，只是 Git 在盯着它。
提交 Commit
一次存档，带一句说明「我改了什么」。存在本地，还没上传。
分支 Branch
从主线复印一份草稿。随便改，改坏了扔掉，正本不受影响。
推送 / 拉取 Push / Pull
Push 把本地存档传上云端；Pull 把云端最新拉回本地。↑ 是你没传的，↓ 是你没拉的。
PR · Pull Request
请求把草稿合并进主线。合并前可以先看改了哪些地方、要不要讨论。
README
仓库首页的说明文件。别人点进来第一眼看到的，就是它。

三、图形界面：三步循环

  1. 改文件 —— 在仓库文件夹里编辑、新建、删除文件。
  2. Commit —— 左下角 Summary 填说明，点 Commit 存档到本地。
  3. Push —— 右上角点 Push origin 传到云端（新分支第一次是 Publish branch）。

右边按钮出现 ↓1，说明云端有新内容，点 Pull origin 拉下来。

四、命令行常用命令

命令作用
cd 路径进入某个文件夹
git status看当前分支和有没有改动，动手前先看一眼
git add 文件把文件放进待存档清单
git commit -m "说明"存档到本地（说明先用英文）
git push上传到 GitHub
git pull拉取云端最新内容
git log --oneline看历史记录，每条一行；出现 (END) 按 q 退出
git restore 文件丢弃还没存档的改动
git reset --soft HEAD~1撤销最近一次提交，改动内容保留
git revert 编号抵消一次已经上传的提交，不破坏历史
git clone 网址把整个仓库下载到本地
git switch 分支切换分支
git switch -c 新分支新建一个分支并切过去

五、改错了怎么办

情况做法
改了还没 commitgit restore 文件 直接回到上次存档的样子
commit 了还没 pushgit reset --soft HEAD~1 撤掉存档，改动还在
已经 push 了git revert 编号 生成一次「反悔提交」，不要强推
图形界面里History 标签里右键某条记录，有 Undo 和 Revert
两条底线：第一，密码、密钥、API Key 永远不要传上公开仓库，git 会永久保留历史。第二，已经被别人拉取过的提交，不要用 reset 强推，会把别人的仓库搞坏。

六、不该上传的东西

在仓库根目录放一个 .gitignore 文件，把不需要跟代码走的东西写进去：模型权重（*.pt、*.onnx）、数据集（data/）、训练输出（runs/）、Python 缓存（__pycache__/）、打包产物（build/、dist/）。
